<h1 align="center">
    NeoHellwal for <a href="https://github.com/neovim/neovim">Neovim</a>
</h1>

<p align="center">
    <b>NeoHellwal</b> is a Neovim colorscheme plugin that automatically fetches and applies colors generated by <a href="https://github.com/danihek/hellwal">Hellwal</a>, featuring plenty of configuration options and support for various plugins within the Neovim ecosystem.
</p>

> [!IMPORTANT]
> NeoHellwal is a Hellwal-based shameless prewrite of [NeoPywal](https://github.com/RedsXDD/neopywal.nvim)
>
> If you find this project useful give a ⭐ to [RedsXDDD](https://github.com/RedsXDD) since he has done all the hard work, and I'm just a thief. 😊
> 
> Hellwal's [`colors.vim` template](https://github.com/danihek/hellwal/blob/main/templates/colors.vim) must be installed in `~/.config/hellwall/templates` for palette generation.

<!-- panvimdoc-ignore-end -->

## Features

- Highly configurable with ability to change [color definitions](./docs/neohellwal-colors.md) and [highlight groups](./docs/neohellwal-highlights.md).
- True color support for terminals.
- Support for dark and light themes.
- Importable and customizable [color palette](./docs/neohellwal-palettes.md).
- Fail safe fallback theme if required palette files can't be loaded.
- Supports [Hellwal](https://github.com/danihek/hellwal) (requires installing Hellwal's [`colors.vim` template](https://github.com/danihek/hellwal/blob/main/templates/colors.vim); see the [palette guide](./docs/neohellwal-palettes.md#hellwal)).
- Automatic reloading of the colorscheme when Hellwal generates a new theme.
- Support for LSP, treesitter and [a bunch of plugins](./docs/neohellwal-plugins.md).
- Enhanced syntax highlighting for [fileformats](./docs/neohellwal-fileformats.md) (without treesitter).
- [Compiled](#-compilation) user's configuration for fast startup times.
- [Interactive](#-interactive-mode) mode for live config re-loading.

## Installation

[lazy.nvim](https://github.com/folke/lazy.nvim)

```lua
{
    "bitterhalt/neohellwal.nvim",
    name = "neohellwal",
    lazy = false,
    priority = 1000,
    opts = {},
}
```

[packer.nvim](https://github.com/wbthomason/packer.nvim)

```lua
use { "bitterhalt/neohellwal.nvim", as = "neohellwal" }
```

[mini.deps](https://github.com/echasnovski/mini.deps)

```lua
now(function()
    add({
        source = "bitterhalt/neohellwal.nvim",
        name = "neohellwal",
    })
end)
```

[vim-plug](https://github.com/junegunn/vim-plug)

```vim
Plug "bitterhalt/neohellwal.nvim", { "as": "neohellwal" }
```

## Usage

To activate the theme, add the following to your Neovim config:

```lua
    vim.cmd.colorscheme("neohellwal")
```

Or call the colorscheme with vim script:

```vim
colorscheme neohellwal
```

> [!Note]
> Make sure to run `:colorscheme neohellwal` or `vim.cmd.colorscheme("neohellwal")`, otherwise the colorscheme won't be loaded.

### Light Themes

Hellwal can generate a light palette with its `--light` option:

```sh
hellwal -i /path/to/your/image --light
```

Then load it the same way as any other Hellwal palette:

```vim
colorscheme neohellwal
```

NeoHellwal uses Neovim's `vim.o.background` setting (see `:h background`) to choose the appropriate style, so keep it consistent with the palette Hellwal generated.

## Compilation

NeoHellwal can pre-compute your configuration and store the results in a compiled lua file stored into the system's cache directory, which then gets loaded when the colorscheme is applied. This approach greatly improves performance and reduces the total execution time.

Note that you can always manually recompile NeoHellwal with the `:NeoHellwalCompile` command. But that shouldn't be needed since NeoHellwal is capable of automatically recompiling the colorscheme when any change is detected on the user configuration or when Hellwal generates a new theme.

## Interactive Mode

NeoHellwal allows for an easy way to make changes to it's config and see the results live by exposing the command `:NeoHellwalInteractive`.

This command will attach an autocmd to the current buffer that executes on BufferWritePost. The autocmd will clear NeoHellwal's internal state and re-compute it's config from the newly saved file. Which in turn will update the colorscheme accordingly.

There are a few things to note:

- This requires executing `luafile` on the current file. Any syntax errors will throw errors.
- If you are using packer and have NeoHellwal's config in a `config = function() end` block, this will not work as packer would require to be re-compiled and the compiled file sourced.
