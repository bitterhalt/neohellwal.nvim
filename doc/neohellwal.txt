FEATURES                                                 *neohellwal-features*

- Highly configurable with ability to change color definitions <./docs/neohellwal-colors.md> and highlight groups <./docs/neohellwal-highlights.md>.
- True color support for terminals.
- Support for dark and light themes.
- Importable and customizable color palette <./docs/neohellwal-palettes.md>.
- Fail safe fallback theme if required palette files can’t be loaded.
- Supports Hellwal <https://github.com/danihek/hellwal> (requires installing Hellwal’s `colors.vim` template <https://github.com/danihek/hellwal/blob/main/templates/colors.vim>; see the palette guide <./docs/neohellwal-palettes.md#hellwal>).
- Automatic reloading of the colorscheme when Hellwal generates a new theme.
- Support for LSP, treesitter and a bunch of plugins <./docs/neohellwal-plugins.md>.
- Enhanced syntax highlighting for fileformats <./docs/neohellwal-fileformats.md> (without treesitter).
- Compiled user’s configuration for fast startup times.
- Interactive mode for live config re-loading.


INSTALLATION                                         *neohellwal-installation*

lazy.nvim <https://github.com/folke/lazy.nvim>

>lua
    {
        "bitterhalt/neohellwal.nvim",
        name = "neohellwal",
        lazy = false,
        priority = 1000,
        opts = {},
    }
<

packer.nvim <https://github.com/wbthomason/packer.nvim>

>lua
    use { "bitterhalt/neohellwal.nvim", as = "neohellwal" }
<

mini.deps <https://github.com/echasnovski/mini.deps>

>lua
    now(function()
        add({
            source = "bitterhalt/neohellwal.nvim",
            name = "neohellwal",
        })
    end)
<

vim-plug <https://github.com/junegunn/vim-plug>

>vim
    Plug "bitterhalt/neohellwal.nvim", { "as": "neohellwal" }
<


USAGE                                                       *neohellwal-usage*

To activate the theme, add the following to your Neovim config:

>lua
        vim.cmd.colorscheme("neohellwal")
<

Or call the colorscheme with vim script:

>vim
    colorscheme neohellwal
<


  [!Note] Make sure to run `:colorscheme neohellwal` or
  `vim.cmd.colorscheme("neohellwal")`, otherwise the colorscheme won’t be
  loaded.

ALTERNATIVE VARIANTS ~

NeoHellwal can also take advantage of Neovim’s `vim.o.background` option (see
|background|) to dynamically adjust the color palette on the fly. This allows
you to switch between light and dark colorscheme variants.

>vim
    colorscheme neohellwal-dark
    " or
    colorscheme neohellwal-light
<


NOTE ON LIGHT THEME ~

NeoHellwal can convert the existing Hellwal palette into a light theme palette.
To achieve this, NeoHellwal uses the functions under the utils
<./docs/neohellwal-utils.md> to modify the HSL colorspace values of your
original dark theme palette.

This conversion may not always create the best results: some palettes may have
unreadable text or colors that become too similar. In general, however, results
are good.

To use a genuine light theme with NeoHellwal, generate a light palette with
Hellwal’s `--light` option.

>sh
    hellwal -i /path/to/your/image --light
<

This makes Hellwal generate a light palette, which you can load with NeoHellwal
using the standard `:colorscheme neohellwal` command.


  [!IMPORTANT] By default, when loading the colorscheme with the standard
  `:colorscheme neohellwal` command, NeoHellwal will automatically detect and
  load the corresponding colorscheme variant based on the current value of
  `vim.o.background`. Neovim may set `vim.o.background` to `light` when Hellwal
  generates a light palette, causing NeoHellwal to select its light variant. Use
  `:colorscheme neohellwal-dark` to prevent automatic variant selection.
This is an unfortunate "bug" of NeoHellwal with a behavior that’s actually
intended to work that way. If you want to avoid this issue, always load
NeoHellwal with:

>vim
    colorscheme neohellwal-dark
<

Instead of:

>vim
    colorscheme neohellwal
<

COMPILATION                                           *neohellwal-compilation*

NeoHellwal can pre-compute your configuration and store the results in a
compiled lua file stored into the system’s cache directory, which then gets
loaded when the colorscheme is applied. This approach greatly improves
performance and reduces the total execution time.

Note that you can always manually recompile NeoHellwal with the
`:NeoHellwalCompile` command. But that shouldn’t be needed since NeoHellwal
is capable of automatically recompiling the colorscheme when any change is
detected on the user configuration or when Hellwal generates a new theme.


INTERACTIVE MODE                                 *neohellwal-interactive-mode*

NeoHellwal allows for an easy way to make changes to it’s config and see the
results live by exposing the command `:NeoHellwalInteractive`.

This command will attach an autocmd to the current buffer that executes on
BufferWritePost. The autocmd will clear NeoHellwal’s internal state and
re-compute it’s config from the newly saved file. Which in turn will update
the colorscheme accordingly.

There are a few things to note:

- This requires executing `luafile` on the current file. Any syntax errors will throw errors.
- If you are using packer and have NeoHellwal’s config in a `config = function() end` block, this will not work as packer would require to be re-compiled and the compiled file sourced.
